# NeoWave website

The redesigned website for **NeoWave**, a building-automation and industrial IoT manufacturer, with a rebuilt
product code generator and an admin for the generator data.

**Live:** https://neowave-site.vercel.app · **Admin:** https://neowave-site.vercel.app/admin

| Page | What it is |
| --- | --- |
| `/` | Homepage: product families, featured switch, solutions, stats, news |
| `/products` | Catalog of 60 devices in 13 categories, with search, filters and 82 datasheets |
| `/generator` | Product code generator: build, decode and share ordering codes, then send one for a quote |
| `/career` | Careers, with an open-application form |
| `/news` + 3 articles | News & events |
| `/contact` | Contact form, details and map |
| `/admin` | Signed-in editor for the generator data (models, options, photos, features, team) |

## How it works

```
site/        the static website Vercel serves (outputDirectory), including site/admin
api/         Vercel functions: admin.js (all admin routes), generator.js (public data), media.js (photos)
lib/         server code shared by the functions: db, auth, generator data logic, photo storage
scripts/     vercel-build.mjs, the build step Vercel runs on every deploy
gen/         Python scripts that generate the pages from data, plus local tools (not deployed)
dev-server.mjs   local stand-in for Vercel (same functions, headers and rewrites)
```

- **Pages are static HTML.** `site/index.html` is written by hand and is the template: the nav, footer and CTA
  of every other page are copied from it by `gen/chrome.py`. The other pages are generated by the scripts in
  `gen/` from data (`gen/catalog.json`, `gen/news.json`, the generator dataset).
- **Motion** uses GSAP + ScrollTrigger and Lenis smooth scrolling (`site/assets/js/main.js`). Animations are always
  on; add `?motion=reduced` to a URL to turn them off for that visit.
- **The product code generator** reads its data from `/api/generator`, which serves the latest published snapshot
  from Postgres. If the API is down it falls back to `site/assets/data/generator.json`.
  Ordering code = model base code + `-` + each option group's chosen code, in order.
- **Generator data** lives in Neon Postgres, schema `pcg` (families, product types, features, models, option
  groups, options, audit log, admin users, sign-in attempts, snapshots). Admins edit it at `/admin` and press
  **Publish to site**; the public generator picks the change up within about a minute, with no redeploy.
- **Product photos** uploaded in the admin go to Neon object storage (S3-compatible, private bucket) and are served
  through `/media/products/<file>`.
- **Analytics:** Vercel Web Analytics on every public page (not the admin).

## Working on it

Requirements: Node 22 and Python 3.12.

```bash
npm install
bash gen/build_all.sh        # regenerate every page, cache-bust CSS/JS, rebuild 404/robots/sitemap
node dev-server.mjs          # http://localhost:5530 (needs gen/.env, see below)
```

Always run `bash gen/build_all.sh` after changing a build script, the homepage, CSS or JS. It rewrites the
`?v=` hashes so browsers load the new files, and turns `products.html` links into clean URLs like `/products`.
Commit the regenerated `site/` files too: Vercel serves `site/` as committed and does not run the Python build.

| Script | Builds |
| --- | --- |
| `gen/build_products.py` | `products.html` from `gen/catalog.json` |
| `gen/build_career.py` | `career.html` |
| `gen/build_pages.py` | `news.html`, the 3 articles, `contact.html` |
| `gen/build_generator.py` | `generator.html` |
| `gen/build_seo.py` | `404.html`, `robots.txt`, `sitemap.xml` (set `SITE_URL` here when the domain changes) |
| `gen/version_assets.py` | cache-busting, clean URLs, the admin photo list |
| `gen/pcg_db.py export` | refreshes the static generator fallback from the database (`build_all.sh --db`) |

## Deploying

Pushing to `main` deploys to production on Vercel. To deploy by hand instead:

```bash
npx vercel deploy --prod
```

## Configuration

Secrets are never committed. Locally they live in `gen/.env` (git-ignored); in production they are Vercel
environment variables:

| Variable | Used for |
| --- | --- |
| `DATABASE_URL` | Postgres connection for the restricted `pcg_app` role (can only use schema `pcg`) |
| `SESSION_SECRET` | signs admin session cookies |
| `NEON_S3_ENDPOINT`, `NEON_S3_KEY_ID`, `NEON_S3_SECRET`, `NEON_S3_REGION`, `NEON_S3_BUCKET` | product photo storage |

## Security

- The site's functions connect as `pcg_app`, a database role limited to schema `pcg`.
- Admin passwords are hashed with scrypt. Sessions are signed HttpOnly, Secure, SameSite=Strict cookies that expire
  after 8 hours. Changing a password signs out that user's other sessions.
- Failed sign-ins are rate-limited (8 per 15 minutes per IP and per account). Admin API calls must carry a custom
  header, which blocks cross-site requests.
- `/admin` is served with a strict Content-Security-Policy, `X-Frame-Options: DENY` and `noindex`.

More detail on the admin, publishing and photo uploads: [gen/README.md](gen/README.md).
